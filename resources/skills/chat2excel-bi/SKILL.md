# Chat2Excel 业务分析总纲

这是 Chat2Excel 的系统级分析流程。它不针对某一张表，而是规定在任何业务数据问题中如何选工具、如何定口径、如何交付结果。

## 适用场景

- 用户问“多少、趋势、变化、对比、排名、占比、异常、明细、导出”等需要基于导入数据回答的问题。
- 用户刚导入 Excel/CSV，还在问“这些数据能看什么”。
- 需要把查询结果做成图表或 Excel 文件交付。

不适用：纯概念解释、与导入数据无关的闲聊、要求修改数据库或读取外部文件的请求。

## 工具地图

| 场景 | 首选工具 | 说明 |
| --- | --- | --- |
| 不知道有哪些表 | `list_tables` | 返回物理表名、显示名、行数、表说明 |
| 第一次使用某张表 | `describe_table` | 列名/类型、空值率、唯一值、min/max、样本行 |
| 取数或聚合 | `query_database` | 单条只读 SELECT，默认最多 2000 行、预览 50 行 |
| 50 行不够看 | `read_query_page` | 翻页读取同一个 queryId 的结果 |
| 做趋势/对比图 | `create_chart` | 必须基于 `query_database` 返回的 queryId |
| 用户要下载/导出 | `export_query` | 导出 xlsx/csv 到应用导出目录 |
| 需要领域方法 | `read_skill` | 读取 `chat2excel-query-recipes` 或 `chat2excel-excel-report` |

## 标准流程

1. **确认数据范围**：不确定表名时先 `list_tables`。只有一个明显相关的表且系统提示已给出完整结构时，可跳过。
2. **理解字段**：第一次查询某张表前用 `describe_table`。重点看日期列格式、金额列类型、分类值样本、空值率。不要凭列名猜含义。
3. **先聚合再取数**：用 `query_database` 写聚合 SQL。除非用户明确要看明细，否则不要 `SELECT *`。
4. **图表按需生成**：只有用户要求图表，或趋势/对比用文字明显更难理解时才 `create_chart`。图表必须复用查询结果。
5. **交付时说明口径**：回答里写清时间范围、筛选条件、聚合方式、行数或样本量。导出时说明文件路径和行数。

## 口径检查清单

回答前逐项自检：

- **时间**：用的是哪一列？按日/周/月/年聚合？区间是否含首尾？
- **金额**：含税/不含税？含退款/不含退款？单位和币种？
- **去重**：订单数用 `COUNT(DISTINCT order_id)` 还是行数 `COUNT(*)`？
- **占比**：分子分母是否来自同一口径？占比之和不是 100% 时是否解释（多选、空值、重复）？
- **排名**：按哪个指标排序？并列如何处理？类别过多是否取 Top N 并说明其余合计？
- **缺失**：空值被计入哪个分组？是否需要单独列出“未知”？

如果问题含糊且会显著改变结果，用一句话说明假设后继续；不要为了追问而停下整轮分析。

## 输出格式

结论先行，再给依据：

1. 一句话结论（带关键数字）。
2. 2-4 条支撑事实（口径、时间范围、对比对象）。
3. 必要时给建议或下一步，但不要把猜测写成事实。
4. 不堆 SQL 术语；用户要看 SQL 时再解释。

示例：

> 华东区 2024 年销售额 1,284 万元，同比增长 18.6%，是四个区域中增速最快的。
>
> - 口径：订单表有效订单，按 `order_date` 归月，不含退款。
> - 华东 2024 年 1,284 万元，2023 年 1,083 万元。
> - 增长主要来自 3 月和 9 月，两个月合计贡献增量的 62%。

## 反模式

- 不查表结构就直接写列名，导致“column not found”。
- 用 `SELECT *` 把上万行结果塞给模型，然后声称“数据太多”。
- 查询被截断（`truncated=true`）还基于前 2000 行下全局结论。
- 图表编码列与查询结果列名不一致，或自己编造图表数据。
- 没有查询就给出数字；把行业经验当成用户数据。
- 要求导入文件时擅自读取本地路径；导入必须由用户在数据页完成。

## 回答“数据能看什么”

当用户刚导入数据、没有明确问题时：

1. `list_tables` 看表清单和行数。
2. 对最相关的 1-3 张表 `describe_table`。
3. 给出 3-5 个可执行的分析方向（趋势、区域对比、Top 商品、异常月份等），每个方向说明用哪些列。
4. 不要一次性跑很多查询；先让用户选方向。
